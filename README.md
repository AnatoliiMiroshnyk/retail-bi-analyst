Описание проекта
Название: Retail BI Analyst
Тип: Настольное приложение (Windows, Python 3.x + PySide6) для анализа продаж, клиентов и товарного ассортимента в малом бизнесе (магазин, интернет‑магазин, кафе).

Приложение загружает данные из CSV/SQLite, позволяет фильтровать и агрегировать их, строит диаграммы, считает ключевые бизнес‑метрики (выручка, маржа, LTV, RFM‑классификация клиентов) и формирует отчёт, который можно экспортировать. Это типичный кейс для направления «Бизнес‑информатика»: цифровая поддержка управленческих решений на основе данных.

Цели и ценность для бизнеса
Помочь владельцу/менеджеру малого бизнеса понять:

какие товары приносят основную прибыль;

какие клиенты наиболее ценные;

в какие периоды падают или растут продажи.

Дать удобный инструмент для:

быстрой проверки гипотез (например, акции, скидки);

планирования закупок и маркетинга;

подготовки презентаций для инвесторов или руководства.

Основные сценарии использования
Импорт данных:

Пользователь выбирает файл CSV (экспорт из 1С, ERP, интернет‑магазина) или подключается к локальной SQLite‑БД.

Настройка фильтров:

Фильтр по периодам (дата от/до), по категориям товаров, по типам клиентов.

Просмотр метрик и дашборда:

Основные KPI: общая выручка, средний чек, количество уникальных клиентов, количество транзакций.

Диаграммы: динамика выручки по дням/месяцам, топ‑5 товаров, распределение клиентов по RFM‑сегментам.

Формирование отчёта:

Генерация текстового отчёта с основными выводами и сохранение в файл (например, Markdown или HTML).

Экспорт/сохранение:

Сохранение настроек и фильтров для повторного анализа.

Функциональные требования
Импорт данных:

Загрузка из CSV (UTF‑8, разделитель ; или ,).

Альтернативно — чтение из SQLite‑БД.

Обработка данных:

Очистка (игнорирование некорректных строк, обработка пустых значений).

Агрегация по датам, товарам, клиентам.

Аналитика:

Расчёт KPI: выручка, средний чек, число транзакций, число уникальных клиентов.

RFM‑анализ (Recency, Frequency, Monetary) клиентов.

Топ‑N товаров по выручке и количеству продаж.

GUI:

Главное окно с вкладками: «Данные», «Аналитика», «Графики», «Отчёт».

Табличный просмотр исходных данных.

Фильтры (виджеты выбора дат, списка категорий и клиентов).

Диаграммы (bar chart, line chart) встроенные в интерфейс.

Отчёты:

Автоматическая генерация отчёта по результатам анализа (текст + сводные таблицы).

Экспорт отчёта в файл (Markdown или HTML).

Нефункциональные требования
Стек: Python 3.10+, PySide6 (Qt for Python), pandas, matplotlib или PySide6 Charts.

Архитектурный стиль: разделение на уровни:

data (репозиторий, загрузка/сохранение);

domain/analytics (логика расчётов);

presentation (GUI).

Это соответствует рекомендациям использовать паттерны MVC/MVVM при разработке GUI с PySide6.

Производительность: обработка наборов данных до ~100k строк без заметного зависания; длительные операции выносятся в отдельные потоки, чтобы не блокировать UI.

UX: современный, интуитивный интерфейс с логичной структурой меню, понятными подписями и минималистичной цветовой схемой, соответствующей рекомендациям по дизайну меню и цветовой палитры для Qt‑приложений.

Код‑стайл: PEP 8, типизация (type hints), docstring’и, единый стиль импортов.

Архитектура проекта
Слои:

data — работа с источниками данных:

модуль data_loader.py для CSV/SQLite;

абстракция SalesRepository для получения и фильтрации данных.

domain — бизнес‑логика:

модуль analytics.py c функциями расчёта KPI и RFM;

модели: SaleRecord, CustomerMetrics, ProductMetrics.

ui — графический интерфейс:

модуль main_window.py с классом MainWindow(QMainWindow);

отдельные виджеты для таблиц, фильтров и графиков.

reports — генерация отчётов:

модуль report_generator.py для создания текстового отчёта (Markdown/HTML).

Такое разделение делает код более поддерживаемым и «питоничным», что совпадает с подходами к структурированию PySide6‑приложений с использованием чётких модулей и классов.

Модель данных
Минимальный набор полей (на уровне CSV/БД):

sale_id — идентификатор транзакции.

sale_date — дата/время продажи.

customer_id — идентификатор клиента.

customer_name — имя клиента.

product_id — идентификатор товара.

product_name — название товара.

category — категория товара.

quantity — количество.

unit_price — цена за единицу.

total_price — сумма по строке (можно считать как quantity * unit_price).

Дополнительно: cost_price (себестоимость) для расчёта маржи.

На основе этих полей строятся таблицы продаж, агрегаты по товарам и клиентам, а также RFM‑метрики.
